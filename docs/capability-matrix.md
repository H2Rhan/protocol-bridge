## 缓存计价与折扣

| 维度 | Anthropic | OpenAI |
|---|---|---|
| 写入 | 5 分钟档 1.25x / 1 小时档 2x | 无写入溢价 |
| 读取 | 0.1x（省 90%） | GPT-4o/o 系省 50% / GPT-4.1 系省 75% / GPT-5 系省 90% |

## 硬约束（实验已复现/判决）

- 4 断点上限：第 5 个 cache_control 返回 400（exp7 实测，非静默降级）。
- 最小可缓存长度：低于阈值**静默不缓存**（exp3/exp12、E23 实测）；阈值逐模型查表，不可外推。
- 缓存条目在首个响应开始后才可用：对照实验须先串行预热再放量（E30/E32 实测并发冷启动重复写入是常态，需 single-flight）。
- max_tokens:0 预热：官方支持；禁带 stream/thinking/structured outputs/tool_choice(tool,any)；Batches 不支持。
- ~~20-block 回看窗口~~：**已证伪删除**（exp5/7/11：60 块 10872 token 仍 100% 命中）。真正的硬约束是最小可缓存长度，不是 block 数。

## 决策记录：手动断点 vs 顶层自动缓存（2026-09-09 补）

选择**块级手动 4 断点**（3 固定 + 1 滚动），不用顶层自动 `cache_control`，理由：

1. 自动缓存与显式断点共用 4 个槽位——开自动就只剩 3 个显式位，分层布局放不下；
2. 自动缓存在四个边界上会 400 或静默降级（TTL 冲突 / 槽位占满 / 末块不合格时向前回溯），命中率变得不可预测，与「命中率北极星可观测」目标冲突；
3. 手动断点的位置由 IR 的 L1/L2 分层直接决定（tools 后 / system 后 / 历史静态段后 / 滚动尾部），策略可进配置、可进测试。
